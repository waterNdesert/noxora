# Feature-by-Feature Breakdown & Execution Paths

This document provides an end-to-end trace of Onyx's primary capabilities, mapping user triggers to backend execution paths, key files, and data state modifications.

---

## 1. Unified Knowledge Search & Question Answering

### Description
Enables users to ask complex questions across internal corporate documents, returning synthesised answers backed by verifiable inline citations.

### End-to-End Execution Path:
1. **User Action**: Enters a prompt in the `/app` chat input and presses Enter.
2. **Frontend Layer**: `web/src/hooks/useChatStream.ts` dispatches a streaming `POST` to `/api/chat/send-message`.
3. **API Proxy**: `web/src/app/api/[...path]/route.ts` forwards the request with auth cookies to `backend/onyx/main.py`.
4. **Chat Backend Handler**: `backend/onyx/server/query_and_chat/chat_backend.py` parses parameters and calls `process_message()` in `backend/onyx/chat/process_message.py`.
5. **Tool Invocation**: The core LLM loop (`backend/onyx/chat/llm_loop.py`) triggers the built-in search tool (`backend/onyx/tools/tool_implementations/search/search_tool.py`).
6. **Retrieval**: OpenSearch performs hybrid retrieval (vector k-NN + BM25 keyword matching) filtered by the user's ACL permissions.
7. **Reranking**: The cross-encoder reranker rescores candidate passages.
8. **Generation**: The LLM streams the synthesized answer, with inline citations added by `backend/onyx/chat/citation_processor.py`.
9. **Persistence**: `save_chat.py` records the user prompt, assistant response, citations, and token usage into PostgreSQL.

## 2. Personas (Custom AI Assistants)

### Description
Allows administrators and curators to configure purpose-built assistants with tailored system prompts, attached document sets, specialized models, and tool access.

### End-to-End Execution Path:
1. **Creation**: Admin creates a persona in `/admin/personas`, defining:
   - System prompt instructions.
   - Associated document sets (e.g., "Engineering Docs", "HR Policies").
   - Tool permissions (Search, Python Interpreter, Web Search).
2. **Persistence**: Saved via `POST /api/admin/persona` to the `persona` table in PostgreSQL (`backend/onyx/db/persona.py`).
3. **Execution**: When a user selects the persona in `/app`:
   - `llm_loop.py` binds the persona's prompt as the system message.
   - Queries are automatically filtered to the persona's allowed document sets.

## 3. Model Context Protocol (MCP) Integration

### Description
Connects external tools and servers to Onyx using Anthropic's Model Context Protocol (FastMCP), enabling Onyx to invoke APIs, database queries, and external agent skills.

### End-to-End Execution Path:
1. **Server Registration**: Admin registers an MCP server URL or command in `/admin/mcp`.
2. **Dynamic Tool Discovery**:
   - `backend/onyx/tools/tool_constructor.py` connects to the MCP server endpoint over stdio or SSE.
   - Queries the server's tool manifest (`tools/list`).
   - Converts MCP tool schemas into Onyx tool definitions.
3. **Execution**:
   - During chat, when the LLM emits an MCP tool call, `backend/onyx/tools/tool_runner.py` dispatches the arguments to the external MCP server.
   - The result is captured and injected back into the LLM context.

## 4. Python Code Interpreter Sandbox

### Description
Executes Python scripts generated by the LLM in an isolated container to perform data analysis, mathematical calculations, and chart generation.

### End-to-End Execution Path:
1. **Trigger**: The LLM determines a query requires code execution (e.g., "Plot monthly revenue from this table").
2. **Tool Dispatch**: The `python_interpreter` tool sends the code block to the sandboxed `code-interpreter` container (`backend/onyx/tools/tool_implementations/python/`).
3. **Isolated Execution**:
   - Code runs in an ephemeral Python environment with restricted network access and resource limits.
   - Standard output, standard error, and generated image files (PNG/SVG) are captured.
4. **Result Delivery**: Text output and images are stored in MinIO/S3 and displayed directly in the chat stream.

## 5. Slack & Discord Bots

### Description
Allows teams to interact with Onyx directly inside workplace communication channels.

### End-to-End Execution Path:
1. **Event Reception**:
   - Upstream Slack webhook hits `/api/manage/slack-bot/events` (`backend/onyx/server/manage/slack_bot.py`).
   - Validates Slack request signature using `SLACK_SIGNING_SECRET`.
2. **Message Processing**:
   - Detects channel mention or direct message.
   - Dispatches a background Celery task (`backend/onyx/onyxbot/slack/`).
3. **Response Dispatch**:
   - Queries the search and RAG pipeline using the bot's configured persona.
   - Posts the reply into the Slack thread with citations and feedback buttons.

---

## 6. Document Access Control & Permission Sync

### Description
Mirrors access control rules from upstream sources so users only see search results they are authorized to view.

### End-to-End Execution Path:
1. **Ingestion**: Connectors capture document owners, shared user emails, and group IDs.
2. **Permission Sync Task**: Celery periodically runs `sync-permissions` (`backend/onyx/background/celery/tasks/docfetching/`).
3. **Index Update**: OpenSearch updates the `access_control_list` array on affected chunk documents.
4. **Query Enforcement**: Every search query strictly injects user email and group IDs as mandatory `bool.filter` constraints in OpenSearch.
